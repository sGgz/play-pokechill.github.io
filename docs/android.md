# 安卓 APK 与资源热更新

安卓版本复用现有网页游戏，将完整资源装进 APK。页面保持与私人云站点相同的 HTTPS origin：游戏入口、图片、字体、脚本由应用私有目录提供；登录和存档 API 请求继续连接原服务器。不会绕过服务端登录验证，不需要跨域放行或在 APK 中保存 GitHub token。

## 首次构建

需要 Node.js 24、JDK 17 或更高版本、Android SDK 的 `platforms;android-35` 和 `build-tools;35.0.0`。设置 `JAVA_HOME` 和 `ANDROID_HOME`，或者使用已有 Android Studio 安装。项目内 Gradle wrapper 固定 Gradle 8.11.1，安卓插件固定 8.9.2。本机独立工具目录 `E:/DevCache/pokechill-android` 存在时构建脚本会自动使用，不修改系统全局环境。

在 Git Bash 中运行：

```bash
npm ci
npm run android:build
```

构建读取已忽略的 `cloud-save-worker/wrangler.local.json` 中 `vars.ALLOWED_ORIGIN`。没有本机站点配置时，可以为此命令指定自己的地址：

```bash
POKECHILL_ORIGIN=https://game.example.com npm run android:build
```

域名必须是 HTTPS 根域名，不包含路径、凭据或非标准端口。这里只使用域名，不会将部署配置里的云槽位、Secret 或 GitHub token 打进 APK。真实域名会存在 APK 内，不能把它当作秘密。

命令会重新构建游戏、校验内置资源、执行安卓单元测试和 lint，然后生成签名的 `output/android/PokeChill.apk`。构建使用已经备份的长期签名密钥：

- `.local/android-release.jks`
- `android/signing.local.properties`

这两个文件已备份至私有存档仓库 `sGgz/pokechill-save` 的 `main` 分支：`android-signing/android-release.jks` 和 `android-signing/signing.local.properties`。本地文件仍被源码 Git 忽略。构建缺少其中任意文件时会通过 Git SSH 自动拉取同一提交中的两份备份；需要本机 SSH 对私有存档仓库有读取权限。

也可以单独恢复或核对私有备份：

```bash
npm run android:signing:restore
```

恢复前会验证密码能访问私钥，并核对签名证书 SHA-256 与当前 APK 固定指纹。已有本地文件与远端不一致时停止，不覆盖；仓库无法访问、备份缺失或验证失败时停止，不生成新密钥。本地两份文件齐全且校验通过时，常规构建无需访问签名仓库。密钥和密码不会输出到日志或放进 APK。

以后更新原生 APK 必须沿用同一签名并提高 `android/app/build.gradle` 的 `versionCode`。不要把密钥或密码提交到源码仓库，也不要重新生成密钥来覆盖旧安装。该私有存档仓库包含签名凭据，应继续保持私有。

仅准备内置资源、随后在 Android Studio 中打开 `android/` 时运行 `npm run android:prepare`。

## 手机使用

安装 APK 后，游戏入口和资源全部从本机读取。无网络、云登录过期、更新下载失败时，仍可在云存档面板明确选择“继续本地游戏”。首次启动依然需要选择初始宝可梦。

最低安卓系统为 Android 8.0。游戏仍需要现代网页 API，Android System WebView / Chrome 需为 120 或更高版本；系统版本满足但 WebView 太旧时，应用会提示更新运行组件。

应用顶部提供“云登录”“检查更新”“应用更新”：

1. “云登录”打开应用内的登录窗口，与游戏共享 Cookie；登录后返回游戏，在云存档面板点击“检查连接”，确认当前玩家。
2. 游戏打开、回到前台时检查更新，前台每五分钟再次检查。自动检查至少间隔一分钟，手动检查可随时触发。后台和断网期间不保证获取新版本。
3. 更新下载完成后提示应用更新。点击后先保存本地进度、等待现有存档任务结束、建立恢复备份，再切换完整资源版本并重载。不会在运行中逐个替换脚本。
4. 更新下载需要有效的云登录。登录窗口、云存档 API、更新资源继续受现有服务端鉴权保护。

浏览器和 APK 的本地存储相互独立。迁移进度时，先在浏览器确认云端保存，再在 APK 登录同一玩家并下载云档；也可导出 JSON 后通过安卓文件选择器导入。导出本地存档和恢复备份包会打开安卓的文件保存界面，无需申请整个手机存储权限。

## 后续发布

日常玩法、界面、汉化、图片、字体改动继续使用现有发布命令：

```bash
npm run verify
npm run cloud:deploy
```

`npm run build` 自动产生：

- `dist/build-info.json`：当前游戏版本和构建标识。
- `dist/updates/latest.json`：完整文件清单、每个文件的 SHA-256、大小、资源协议版本。
- `dist/updates/objects/<sha256>`：按内容寻址的资源文件。

脚本、图片、字体、构建工具和依赖锁文件都参与构建标识。清单保留图片大小写别名；安卓通过哈希加载实际对象，不依赖 Windows 大小写不敏感的文件系统。

网页和更新对象作为同一次 Cloudflare Workers 静态资源发布上线。版本清单禁止缓存；已登录用户的不可变哈希对象可长期缓存。手机在版本变化后只下载本机没有的对象，已有 APK 内置对象和校验通过的下载对象都可复用。全部对象校验成功后才将新版标记为可应用。如果服务器发布期间资源不完整、连接中断或空间不足，当前版本保持可用；下次检查会复用已完成的对象继续下载。

安装包大小与下载资源总量不同：首次 APK 内置完整资源，后续通常仅下载变化文件。下载清单本身仍有数百 KB，不是零流量。未变动的图片不会因脚本版本变化而全部重新下载。

## 启动验证与恢复

新版资源激活后处于试运行状态，游戏完成初始化后才确认该版本可用。登录等待、云档冲突选择和“继续本地游戏”等待不会触发超时回退；游戏进入初始化后未能完成、脚本入口无法启动，或应用在确认前被终止，会在当前或下次启动恢复上一版，并阻止反复应用同一个失败版本。需要发布一个新的构建标识才能再次尝试。

每次确认新版本可用后，清理已不再需要的下载对象，保留当前和上一资源版本。APK 内置资源始终保留作为最终回退入口。更新器不会删除 WebView 本地存储、IndexedDB、云档或玩家数据。

**资源回退不会回退存档。** 本地存档版本高于旧游戏版本时，游戏会阻止运行并保留存档与恢复备份，等待修复版本。修改存档格式仍需游戏代码提供兼容迁移；热更新不替代存档兼容设计。源码版本相同但语义不兼容的存档改动必须提高游戏版本。

## 需要新 APK 的改动

安卓权限、原生代码、运行容器、新增原生能力、应用包名或游戏域名变更需要构建新 APK。资源清单的 `nativeApi` 必须与应用兼容，遇到不兼容协议时会提示更新安装包。仅 HTML、CSS、JavaScript、图片和字体变更无需重新安装 APK。

持续集成执行网页验证及安卓更新器的下载复用、校验失败、断网恢复、进程中断回退和路径边界测试，并生成使用示例域名的调试 APK。实际分发请使用本机私有站点配置构建的签名安装包；CI 调试 APK不能替代私人站点的正式安装包。
